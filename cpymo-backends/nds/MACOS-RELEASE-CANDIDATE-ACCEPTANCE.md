# CPyMO for NDS 1.2.0 — macOS 本机 GUI 验收交接

本任务仅在 **最终背景已内嵌、Windows 与 macOS 使用同一 SHA-256 ROM**、macOS CI 通过实际 MP4→NVL1 冻结转换后交给用户本地 DeepSeek。不得拿早期占位背景研究版测试。

## 给本地 DeepSeek 的操作边界

- 用户本机测试，不能上传其商业游戏、ROM、私人存档或个人文件到第三方；只操作专用临时测试目录。
- **不要改 CPyMO 仓库源码、README、发行配置或任何原游戏文件**。本任务是独立验收，不是继续开发。
- 不要禁用 Gatekeeper、SIP、AMFI，也不要直接运行来源不明的 `sudo`、`xattr -dr` 清除隔离属性等命令。若系统阻止启动，报告完整提示与系统信息，用户自行决定下一步。
- 若设备 Apple Silicon，需要报告实际 CPU 架构、.app Mach-O 架构以及是否已有 Rosetta；不得未经用户许可安装 Rosetta 或其他系统组件。
- 未做的项目标为 **未测试**，不凭截图或静态分析虚构运行通过。

## 实机检查顺序

1. 记录 macOS 版本、芯片架构与系统语言；解压 RC ZIP，记录 SHA-256 与文件清单，确认存在 `CPyMO-NDS-Converter.app`、`cpymo-nds.nds`、`VERSION.json`、随附说明。
2. 核对 `VERSION.json` 的版本应为 **1.2.0**，`rom_sha256` 应与随包 `.nds` 字节一致；检查是否与交付的官方 ROM SHA 一致；不要移动 / 删除现有用户 TF 卡数据。
3. 尝试在 Finder 中打开 .app。测试窗口字体、下拉框和按钮是否可见及操作。若出现签名／公证／Gatekeeper／Rosetta 提示，记录原文，不强行绕过系统安全设置。
4. 默认状态应为：**NVL1 视频转换启用**、缓存推荐模式、**缺字自动以方框替代并警告**；普通用户不需要先修改高级选项。
5. 使用原创合成小测试游戏，准备合法的 `gameconfig.txt`、`script/START.txt`、背景、测试音频，`video/OPENING.mp4` 可以由许可已明确的本地 FFmpeg 以 `testsrc2`+正弦音生成；不得复制真实商业游戏。
6. 用 Finder GUI 分别选取包含该游戏的 ZIP、普通文件夹（APK 如果有合法自制样本可选测）。检查识别平台优先级、输出新目录，不覆盖既有文件，文件名含中文时也能处理。
7. **默认 NVL1**：不用改变视频模式，转换后核对 `nds-cache/video/` 有 .nvl、manifest 的 `format: NVL1` 且视频没有被省略；输出目录含相同官方 ROM、`pymo/games/...`、`script/`、`nds-cache/` 与 `save/`。
8. **NVA1 可选**：在 GUI 切换模式后独立转换到新路径，检查 `format: NVA1`；然后选跳过视频再转换一次，检查不会误报可播放视频。这两项可按时间优先级简短验收，但必须记录是否真正执行。
9. 缺字：在测试脚本追加当前内置字库没有的字符（如 U+1F984 🦄）；GUI 默认应继续转换，并在日志／输出报告中提示字库缺字，使用 `□`，**原始脚本仍保留原字符并且文件 SHA 不变**。
10. 完成后检查在转换器内点击「打开结果文件夹」能够通过 Finder 打开；取消、路径错误、缺少工具、无权限输出应给出可理解的错误，不应无响应或破坏用户文件。
11. 将本机结果和 CI 区分：记录 UI 是否启动、是否成功完成真实视频转换、配套 ROM SHA、错误弹窗、是否要求 Rosetta、性能明显异常、是否可接受作为普通用户 macOS 下载包。

## 验收报告

请向用户输出：

- 环境：macOS 版本、CPU、是否 Rosetta、GUI 打开方式、安全提示。
- 测试表：安装解压／Finder GUI／默认 NVL1／NVA1／跳过视频／缺字 □ 警告／原始数据保护／输出规范／日志和异常处理，逐项 **通过／失败／未测试**。
- 发现的问题：严重等级、复现步骤、预计影响（阻断发行／仅说明）。
- 证据：原始命令、截屏文件路径、日志、RC SHA256、ROM SHA256（不要带私人游戏素材）。
- 总结：**建议正式发布 / 建议附条件发布 / 阻止发布**，并明确未测项。

完成后将报告交回用户；代码修复统一留给项目维护方决定，不由本地测试代理擅自提交。
